# STM v0.1 — independent adversarial and performance review

Reviewer: genuinely dispatched second-wave Agent 7 (separate from implementation).
Date: 2026-10-28. Scope: integrated local src/stm candidate,
not a deployed model or installed service.

## Reproduce

From the STM repository root with Python 3.12:

    python -m unittest discover -s tests -v
    python benchmarks/bench_stm.py --output benchmarks/results.json

The benchmark corpus is deterministically generated by fixtures():
1,000 updates, 8 early pinned facts, 8 recent unpinned facts, 984 unrelated
messages, 16 exact-answer queries, 256-record working-store limit, and
4,096 UTF-8-byte prompt-context budget. It uses three implementations:

- STM: relevance ranking and required pinned evidence, followed by packing.
- Naive sliding: most recent 20 messages, no relevance or pin handling.
- Uncached bounded recency: latest fitting entries in a 256-record store,
  repacked for each query, no relevance or pin handling.

All three use the same generated messages and UTF-8-byte accounting;
the baselines intentionally represent separate simplistic policies.

## Measured outcome

Exact latest captured values are in `benchmarks/results.json` (single local run).
The 11 independent adversarial unit tests all passed. On the synthetic
16-query fixture, STM retained the exact answer 16/16 times, the recency
baseline 8/16, and the sliding baseline 0/16. Mean context-selection
latency was roughly 4.51 ms for STM, 0.99 ms for recency, and 0.11 ms for
sliding. STM was slower but retained more target evidence.

The STM packed context averaged 4,006 UTF-8 bytes compared with 50,158
for the full unbounded history, a 92.01% byte reduction; this is not a
claim of model-token savings. The peak measured Python allocations during
ingest were 287,600 bytes under tracemalloc; that measurement excludes
native allocations and can be affected by the harness.

The store reported 745 capacity evictions after a deliberate extra mutation,
with 9 pinned records still present. Eight concurrently written isolated
sessions each contained exactly 40 entries. Checkpoint/restore round-tripped
the full record-ID set. Application prefix cache sequence was miss, hit,
miss after invalidation; backend KV reuse was not measured.

## Adversarial discoveries and resolution

1. **Pinned context loss through rank-before-pack:** Original coordinator
   selected top-N records before considering pinned records. Low-scoring
   pinned evidence could disappear without a budget-overflow error.
   Parent integrator changed assembly to include all authorized pinned
   records before packing. The independent regression now passes.
2. **Dedup can erase pinned duplicate identities:** A duplicate pinned
   record may be collapsed by the ranking layer. Coordinator now pulls
   every pinned original from storage; regression passes.
3. **Identity/protocol mismatch:** Core initially used a local Actor type
   while policy required its own Actor, and imported a nonexistent
   StorageBackend name. Parent corrected the integration; append works.
4. **Mixed-clock TTL decisions:** Storage used injected test time but
   governance defaulted to wall time. Parent passes the same session time
   to governance reads. TTL regression passes.

## Remaining bounds and unsupported claims

- Host identity strings are not authentication. The embedding host must
  authenticate tenants/users/agents before creating an STM session.
- The security admission filter is lexical, conservative, and bypassable;
  no semantic prompt-injection resistance is established. Quarantine of
  a known override phrase is demonstrated, not universal poisoning immunity.
- Checkpoints are private-permission JSON, not encrypted. Deleting a
  live record does not retroactively erase separately stored checkpoints.
- Memory is bounded by record/session counts and configured content-size
  limit, not a measured strict total-process RSS cap.
- Embedding effectiveness, real model token counts, backend KV cache reuse,
  live Ollama behavior, and true user-data retrieval accuracy remain
  **UNVERIFIED**.
- Latency measurements are single-process Python selection times; they do
  not measure inference or service tail latency.
- No external reference system was benchmarked under matched runtime and
  datasets in this first pass.

Verdict: The first candidate meets the bounded working-context and
isolation checks of this independent synthetic test. It remains a research
candidate pending realistic traces, model-specific tokenizer validation,
separate code review, and runtime evaluation.
